# Termivance — Agent Execution Constitution

## Product and authority

Termivance is a **Proof-Bounded Software Retirement Protocol**. Frozen route: **GitLab Transcend 2026 / Path A / Start Fresh / Supervised**. Frozen architecture: **one real GitLab Duo Custom Flow agent + deterministic Python authority**. Canonical repository is the newly created, public, MIT-licensed **GitLab** remote, not this starter ZIP. **Before the initial push, no canonical remote exists. Determine whether sponsor onboarding has already provisioned a GitLab project; do not create a competing namespace or use a GitHub repository as the canonical contest remote.** Never invent a GitLab namespace, project, SHA, session, or approval.

The AI agent may inspect context, propose an obligation graph, coordinate work, open/update GitLab items, and explain evidence. Deterministic code owns exact target identity, allowed actions, authorization, mutation, read-back, and verdicts. Model text cannot award `SAFE_TO_RETIRE`, `OBSERVED_ABSENT`, or `RESURRECTION_CONTROLLED`.

## Four macro-batches, no microphases

The only delivery batches are **B1, B2, B3, B4** in `plans/MASTER_PLAN.md`. Mandatory cycle: **ONE comprehensive executor prompt → ONE consolidated execution report → ONE independent full-batch QA → ONE consolidated repair if material defects exist → NEXT full batch**. Execute all related code, tests, CI, integration, and relevant fixes within the active batch. The executor chooses internal work order autonomously. No P-XX subdivisions, per-file approval gates, P-Ω audits, or separate micro-prompts. Never self-award independent QA PASS.

After independent `BATCH PASS ✅`, immediately proceed with the next full-batch prompt. At `BATCH REPAIR ❌`, group all material defects into one repair prompt. Defer harmless README, plan chronology, presentation, and duplicated status discrepancies until **one B4 documentation reconciliation**; do not create documentation-only repairs in B1–B3.

## Evidence and safety invariants

- A successful API mutation is **not** proof of retirement; independently re-read the authoritative system.
- `NOT_RUN` is never `PASS`; a local test or fixture is never live GitLab evidence.
- A stopped GitLab environment **is not** an undeployed GitLab Pages site; GitLab-native status is not proof of absence from independent cloud providers.
- The **sole proposed destructive demo target** is a newly created, isolated disposable GitLab Pages project. The canonical Termivance repository and all other existing projects are expressly out of scope. No GitLab project deletion.
- For Pages unpublishing, bind authorization to immutable numeric project ID, full path, exact resource kind, action, expiry, and one-time/limited use. Revalidate immediately before mutation and refuse ambiguity. Never infer authorization from prose or a successful CI job.
- Unpublish Pages only through the verified GitLab API `DELETE /projects/:id/pages` on that exact authorized disposable project. Check GitLab Pages API and the served Pages URL independently afterward; distinguish a negative observation from universal absence. CDN convergence may be delayed: unknown, errors, or stale evidence are never promoted to verified absence.
- A later Pages redeployment can reverse observed absence. Do not claim `RESURRECTION_CONTROLLED` without live monitoring/control evidence; preserving a historical receipt must not override current observations.
- Never mutate production/shared resources, another project, or an unapproved paid service. Personal-spend target: **$0.00**. Never enable paid plans, on-demand billed credits, credit cards, or upgrades without explicit operator authorization.
- A GitLab Duo flow session is required for real integration evidence. Do not mistake ordinary Chat, API polling, YAML presence, GitLab CI, or mocked logs for a real Custom Flow run. Triggered flows can consume **service-account credits**; check the actual namespace billing boundary before executing.
- Tokens, passwords, personal identifiers, runner secrets, and session values must stay out of git, reports, issues, and public CI logs. Use least-privilege scoped/masked CI variables; never echo secret values.
- Reuse of StillDone or other prior projects is **CONCEPT_ONLY** by default. Original code reuse requires verified MIT-compatible license, immutable source SHA, provenance, contest eligibility, and operator approval. Prefer clean-room code.

## Remote and QA contract

Before changes after bootstrap: inspect `origin/main`, capture starting remote SHA, read Master Plan and HANDOFF, then inspect only relevant code. B1 must discover the eligible sponsor-provisioned GitLab project/namespace before selecting the canonical new remote. The current October 2026 Devpost overview and schedule take precedence over a stale June 2026 rules page at the same /rules URL; confirm any unresolved October-specific eligibility terms with current organizer resources without stalling routine implementation. At batch end: commit, push, re-fetch, and independently compare remote HEAD to reported final SHA. Record changed-file summary, focused test and CI results, original GitLab Duo session URL / project effect, evidence source and timestamp, and `NOT_RUN` checks. A claim of live capability without an observable live event is **blocked**, not passed.

Only genuine access, eligibility, cost, security, or fundamental platform blockers may interrupt a batch. If operator action is unavoidable, provide exact browser URL, Turkish menus/buttons, expected result, and clear payment warning; do not ask for tokens in chat. Never demand operator work the executor can safely do.
