## B3 repair log — retirement authority, absence integrity, durable authorization, QA bridge (2026-10-18, all times UTC)

Independent QA of B3 found the GitHub bridge genuinely operational but identified four material safety-contract defects. All four are repaired in this batch; no new phase was created.

- **A. Retirement authority is now graph-bound.** `retirement.retire_pages()` performs fresh, exact-target discovery, observes the served-URL publication marker, builds the complete obligation graph and evaluates it. A `DELETE` is dispatched only when the deterministic decision is `SAFE_TO_RETIRE`, and only after a second immediate revalidation (fresh discovery + publication probe + decision) against the live provider. Bound into the receipt: decision, snapshot SHA-256 digest, evidence timestamps, publication pre-state and the authorization binding digest. Static policy + authorization success can never override a `BLOCKED`/`INCONCLUSIVE` graph — proven by `test_policy_and_authorization_cannot_override_inconclusive_graph`. Two new mandatory obligations enforce the QA findings: `RETIREMENT_PERMISSION` (effective Maintainer/Owner Pages administration, from the viewer's effective project/group access level **and** the Pages API) and `PAGES_PUBLISHED` (live Pages deployment **and** independently observed marker at the exact URL). Target drift is detected: a changed immutable project id **or** a changed full path during revalidation refuses the mutation.
- **B. Bounded absence proves a real transition.** `bounded_absence()` can no longer award `OBSERVED_ABSENT` from two unrelated `404` responses. It now requires: genuine pre-publication proof (live deployment + observed marker), the pre-state URL bound to the same target and equal to the post URL, a recorded **accepted** authorized unpublish, an independent post-action Pages API read-back, and an independent post-action read-back of the *same* URL, all within the freshness interval. Never-published sites, marker/URL mismatch, unaccepted actions, Cloudflare interstitials, redirects, errors, statuses other than 404/410, and stale or contradictory evidence all fail closed to `INCONCLUSIVE`; a site still served yields `BLOCKED`. Because unauthenticated `*.gitlab.io` reads currently return a Cloudflare interstitial, served-URL evidence for this namespace is `INCONCLUSIVE` even when a site is genuinely live — recorded honestly rather than promoted.
- **C. Authorization is durably single-use and provenance-bound.** `termivance/ledger.py` writes an atomic, `fsync`ed consumption record **before** the mutation (`.termivance/authorization_ledger.json`, gitignored) and verifies the write landed; a crash after reservation burns the authorization. A reloaded authorization JSON in a separate CLI invocation is refused with the ledger recorded in the receipt. `Authorization.from_dict` now refuses provenance-free records; a loaded record must carry a verbatim `operator_approval` block whose `binding` matches the computed authorization digest and whose statement names the exact endpoint `/projects/<id>/pages` and the exact action. An optional HMAC (`TERMIVANCE_APPROVAL_HMAC_KEY`) is enforced when configured. Residual limitation stated honestly: without a configured key the approval is *attributed*, not cryptographically proven; the durable ledger is what makes replay impossible.
- **D. QA bridge completed and fail-closed.** The observer now reads the **current final pipeline** (id, status, ref, jobs, verification job), attempts the verification job trace, and reads the canonical source files at the observed live commit into a SHA-256 source manifest, plus an evidence SHA-256 manifest over every artifact. The historical B2 pipeline is retained only as `b2_history_reference` and is never used as current evidence. `qa_status` is `PASS` only when every mandatory public endpoint is live, the mirror SHA matches the live GitLab main commit, and the current pipeline is bound to that same commit; otherwise `NOT_VERIFIED` with a non-zero exit. `observer/selftest.py` proves drift, unknown-mirror, missing-mandatory-endpoint and absent-canonical-source all yield `NOT_VERIFIED`, and that personal names are redacted while CI job names survive. Verified job trace: `401` unauthenticated → recorded as `NOT_OBSERVED`, never fabricated.
- **E. Scope preserved.** The only approved destructive target remains project `87785099`. Canonical `87779099` and showcase `87777871` remain protected. Diagnostic project `87786164` is disclosed and is never used as a retirement substitute. $0.00 spend; no project deletion attempted; no paid service or credit used.
- **F. Testing.** `189` tests pass locally and in GitLab CI; `ruff` clean. New adversarial coverage: policy/authorization valid while the graph is `INCONCLUSIVE`; authorized target with missing provider observation; two unrelated 404s; a previously nonexistent Pages site; served-URL/marker mismatch; stale and contradictory post-state; authorization reuse across separate invocations; fabricated/provenance-free/non-specific operator approval; HMAC required when keyed; effective Developer-only permissions; a successful `204` DELETE with unusable read-back; reappearance after unpublish; target drift during revalidation; and the mutation allowlist never matching project deletion. `scripts/ci_safety_assertions.py` re-proves six of these network-free inside the pipeline itself.
